# Foraging experiment

The `marlkit.foraging` experiment studies cooperative and competitive resource collection in a small two-dimensional grid. Two independent Q-learning agents move through the environment, collect food, and learn from one of three reward models.

This README documents the implementation behind the launchers and is also loaded by the generic MARLKIT experiment launcher. The launcher menu discovers the three concrete classes in `marlkit.foraging.launchers` automatically.

## Quick start

From the repository root, build and launch the generic menu:

```bash
./gradlew :MLK-experiments:run
```

Select **Foraging experiments**, choose a launcher, and press **Launch selected experiment**. Each simulation starts in a separate JVM, so the menu remains available for additional experiments.

Every concrete launcher can also be started directly from the IDE or from the generated distribution. The default launcher arguments start MaDKit with INFO-level logging and the simulation startup sequence.

## Available launchers

The three launchers use the same environment, deterministic scenario, agents, scheduler, and viewer. They differ only in the reward model.

### Fully cooperative reward

The `FullyCooperativeReward` launcher gives every agent the average of the rewards generated by all agents during the current step. This encourages the agents to optimize collective performance.

**Launcher:** `LauncherForagingFullyCooperative`

### Mixed reward

The `MixedReward` launcher gives each agent the reward computed from that agent's own reaction events. Agents therefore learn independently and can compete for the same resource.

**Launcher:** `LauncherForagingMixedReward`

### Fair mixed reward

The `FairMixedReward` launcher combines each agent's individual reward with the minimum reward observed across agents. It uses $\delta = 0.5$ in the launcher, providing a compromise between individual optimization and fairness.

**Launcher:** `LauncherForagingFairMixedReward`

## Experiment architecture

The package follows the standard MARLKIT experiment composition:

| Component | Implementation | Responsibility |
|---|---|---|
| Launcher base | `launchers.LauncherForaging` | Connects the scheduler, model, viewer, environment, scenario, and reward model. |
| Environment | `EnvForaging` | Maintains the grid state and converts actions into movement and food-collection events. |
| Scenario | `scenario.ScenarioDeterministic1` | Places the two agents and five food units deterministically. |
| Agent | `agent.ForagingAgent` | Configures the independent Q-learning policy and action space. |
| Scheduler | `SchedulerForaging` | Defines episode termination, display, evaluation, and simulation limits. |
| Viewer | `ViewerForaging` | Draws the grid, food, agents, and grid lines. |
| Evaluator | `systemevaluator.ForagingEnvEvaluator` | Records total reward, episode duration, and the lowest agent reward. |

The three concrete launchers only select a reward implementation:

```text
LauncherForaging
├── LauncherForagingFullyCooperative  -> FullyCooperativeReward
├── LauncherForagingMixedReward       -> MixedReward
└── LauncherForagingFairMixedReward   -> FairMixedReward(0.5)
```

## Environment and scenario

`LauncherForaging` creates an `EnvForaging` instance with a `5 × 6` grid and launches two `ForagingAgent` instances. The environment uses `State2DGridInt` with agent positions enabled.

`ScenarioDeterministic1` initializes the experiment with the following coordinates:

| Entity | Coordinates |
|---|---|
| Food | `(4, 0)`, `(4, 1)`, `(1, 2)`, `(2, 2)`, `(4, 2)` |
| Agent 1 | `(3, 2)` |
| Agent 2 | `(0, 4)` |

At each step, an agent chooses one of four actions: move left, right, up, or down. Agents that occupy the same food cell share the food-collection events equally.

The environment emits `MoveEvent` and `FoodCollectedEvent` reaction events. The selected reward model converts these events into rewards before the scheduler builds experiences for learning.

## Agents and learning

Each `ForagingAgent` is an independent `AgentStandard` with no communication module. Its policy and learning configuration is:

| Setting | Value |
|---|---|
| Action space | `Move2DInt.left`, `right`, `up`, `down` |
| Policy | `QValueBasedPolicy` |
| Initial exploration parameter | `1.0` |
| Exploration strategy | `EpsilonGreedyPowerDecay(0.2)` |
| Learning algorithm | `QLearning` |
| Learning rate | `0.2` |
| Discount factor | `0.995` |

The agents observe the environment through the standard MARLKIT observation pipeline. They update their policies from the experiences produced by the scheduler after each environment reaction.

## Reward models

Let $r_i$ denote the reward computed from agent $i$'s reaction events during one step.

### Fully cooperative reward

`FullyCooperativeReward` first computes each agent's individual reward and then gives every agent the average:

$$
R_i = \frac{1}{N}\sum_{j=1}^{N} r_j
$$

This makes the agents' learning targets identical for the current step.

### Mixed reward

`MixedReward` preserves individual rewards:

$$
R_i = r_i
$$

An agent can therefore improve its own return without directly optimizing the other agent's return.

### Fair mixed reward

`FairMixedReward` uses the minimum individual reward as a fairness signal. With the launcher parameter $\delta = 0.5$:

$$
R_i = (1 - \delta)r_i + \delta \min_j(r_j)
$$

The constructor validates $\delta \in [0,1]$. A value of zero is purely individual; a value of one gives every agent the step minimum.

## Simulation lifecycle

`SchedulerForaging` extends `MLKScheduler` and configures the following lifecycle:

1. Launch the environment and two agents.
2. Initialize the deterministic scenario at the start of an episode.
3. Compute observations and request agent actions.
4. Apply movement actions in `EnvForaging`.
5. Generate movement and food-collection reaction events.
6. Convert reaction events into rewards using the selected reward model.
7. Build and collect experiences for both agents.
8. Update the Q-learning policies.
9. End the episode when all food is collected or after 100 time steps.
10. Record evaluator measures and reset the environment for the next episode.

The scheduler configuration is:

| Parameter | Value |
|---|---:|
| Episode duration | `100` steps |
| Maximum episodes | `300000` |
| Display start | after `100000` episodes |
| Display interval | every `10000` episodes |
| Displayed episodes | `1` |
| Display pause | `100` |

## Evaluation and results

`ForagingEnvEvaluator` records three episode measures:

- **TotalReward** — the sum of all event rewards received by all agents.
- **EpisodeDuration** — the number of evaluated time steps in the episode.
- **LowestAgentReward** — the smallest cumulative reward among the agents.

The figures below illustrate the experiment's recorded results. They are stored beside this README in `figures/` and are copied to the runtime classpath by Gradle.

### Episode duration

This measure exposes imbalance: a low value indicates that at least one agent is receiving substantially worse returns than the other.

## Adding a new foraging launcher

To add another reward-model variant:

1. Create a concrete subclass of `LauncherForaging` in `marlkit.foraging.launchers`.
2. Give it a public static `main(String[] args)` method.
3. Add runtime `@LauncherMetadata` with a unique title and README heading anchor.
4. Add a matching `###` section to this README.
5. Keep the package-level `@ExperimentMetadata` and README resource path unchanged unless the experiment becomes a separate package.
6. Run the launcher catalog tests and verify that the README resource and figure links are packaged.

Example metadata:

```java
@LauncherMetadata(
    title = "My Reward Variant",
    documentationAnchor = "my-reward-variant")
```

No catalog or menu list needs to be edited: the generic launcher catalog discovers the new class from its annotation.
